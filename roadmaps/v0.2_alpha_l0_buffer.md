# Neura-Core v0.2 — Alpha: L0 Memory Buffer Engine

> **Objetivo:** El sistema puede registrar, visualizar y exportar conversaciones en tiempo real a través del buffer circular L0 (Redis Streams). El launcher muestra el estado del buffer en vivo.

---

## Stack Adicional Esta Versión

- **Redis:** Redis 7+ en Docker (`docker-compose.yml` incluido)
- **Cliente Redis Rust:** `redis-rs` con soporte async
- **Serialización:** `serde_json` para entradas L0
- **UI Nuevo:** Panel "Memory > L0 Raw Logs" en el launcher

---

## Hito 2.1 — Infraestructura Redis Local con Docker

**Entregable usable:** Redis corriendo localmente, el launcher lo detecta y muestra estado de conexión.

### Sub-metas
- [ ] `docker-compose.yml` con servicio Redis 7 + Redis Insight opcional para depuración local; no forma parte de la aplicación distribuida
- [ ] Comando en Tauri: "Iniciar Redis" arranca el contenedor automáticamente
- [ ] Indicador de conexión en el launcher: verde (conectado) / rojo (desconectado)
- [ ] Panel Settings: configurar host, port y password de Redis
- [ ] Test de ping automático cada 5 segundos con reintento exponencial

### ✅ Revisión Manual Requerida
- Ejecutar `docker-compose up` y verificar que el indicador del launcher cambia a verde
- Detener Redis y confirmar que el indicador cambia a rojo en ≤ 10 segundos
- Cambiar el puerto en Settings y confirmar que el launcher reconecta al nuevo puerto
- Abrir Redis Insight en `http://localhost:8001` y verificar conexión visual

## Hito 2.2 — Ingesta L0: Escritura al Buffer Circular

**Entregable usable:** Formulario manual en el launcher para escribir entradas L0 al stream de Redis.

### Sub-metas
- [ ] Estructura de entrada L0:
  ```json
  { "entryId": "", "timestampMs": 0, "speaker": "user|agent",
    "rawText": "", "prosodyData": { "pitchHz": 0, "energyDb": 0, "speechRateSyllablesSec": 0 } }
  ```
- [ ] Panel "Memory > L0" con formulario: speaker, texto, prosody sliders
- [ ] Botón "Enviar al Buffer" hace `XADD` a Redis con `MAXLEN ~ 200`
- [ ] Contador en vivo: "Buffer: X / 200 entradas"
- [ ] Botón "Flush Buffer" ejecuta `DEL streamKey`
- [ ] `sessionId` y `tenantId` tomados del `neuracore.config.json`

### ✅ Revisión Manual Requerida
- Enviar 5 entradas manuales y verificar en Redis Insight que aparecen en el stream
- Enviar 201 entradas y confirmar que `XLEN` no supera 200 (recorte activo)
- Hacer clic en "Flush Buffer" y confirmar que Redis Insight muestra el stream vacío

## Hito 2.3 — Visualización L0 en Tiempo Real

**Entregable usable:** Feed en vivo de entradas L0 en el launcher, actualizado cada segundo.

### Sub-metas

- [ ] Colores diferenciados: azul para `user`, verde para `agent`

### ✅ Revisión Manual Requerida

- Pausar el feed, enviar 5 entradas, reanudar; confirmar que las 5 aparecen inmediatamente
- Hacer clic en una entrada y verificar que el JSON expandido tiene todos los campos

## Hito 2.5 — Lifecycle Management: TTL & Compresión Sesión

**Entregable usable:** Panel que muestra tiempo de vida restante de cada sesión y permite cerrarla manualmente.

### Sub-metas
- [ ] Cada stream tiene TTL de 24h usando `EXPIRE streamKey 86400`
- [ ] Panel "Sesiones Activas": lista de streams con nombre, entradas, TTL restante
- [ ] Botón "Cerrar sesión" ejecuta `DEL streamKey` y muestra resumen: total entradas, duración
- [ ] Alerta en UI cuando TTL cae por debajo de 1 hora
- [ ] Worker Rust que detecta streams expirados y los elimina de la lista

### ✅ Revisión Manual Requerida
- Crear sesión, esperar 5 segundos y verificar que el TTL decrece correctamente
- Reducir manualmente el TTL a 10 segundos (`EXPIRE key 10`) en Redis CLI y verificar que la alerta aparece
- Cerrar una sesión y verificar que el resumen de entradas coincide con lo visto en el feed
