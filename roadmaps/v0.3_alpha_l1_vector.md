# Neura-Core v0.3 — Alpha: L1 Atomic Facts Index (Vector Search)

> **Objetivo:** El sistema extrae hechos atómicos de las entradas L0 y los indexa como vectores consultables. El launcher visualiza los hechos recuperados y permite hacer búsquedas semánticas manuales.

> **⚠ Adaptación (hito 3.1–3.5):** el índice vectorial vive en `apps/launcher/src/l1/` con un seam `L1Store` con dos implementaciones: `LocalL1Store` (localStorage, sin dependencias) y `QdrantL1Store` (`src/l1/qdrant.ts`, Qdrant real vía REST en `localhost:6333` — colección `tenant_{agent}_l1_facts` 384-d Cosine, upsert de puntos con payload SPO, búsqueda con decay aplicado client-side). La UI permite **Activar Qdrant** (detecta el servidor, crea la colección si falta) o **Volver a local**. Embeddings en el propio webview con `@huggingface/transformers` + `all-MiniLM-L6-v2` (descarga única, sin API externa ni Ollama). El worker auto-extracción (hito 3.5) sustituye `XREAD BLOCK` por polling del buffer L0 local.

---

## Stack Adicional Esta Versión

- **Vector DB:** Qdrant v1.9+ en Docker (`qdrant/qdrant`, puertos 6333/6334) → `QdrantL1Store` en TS (`src/l1/qdrant.ts`), con `LocalL1Store` como fallback sin Docker
- **Embeddings:** OpenAI/Ollama → **adaptado:** `@huggingface/transformers` + `Xenova/all-MiniLM-L6-v2` (384 dims, ONNX local en el webview)
- **Cliente Qdrant:** `qdrant-client` Rust → no aplica (adaptador TS `QdrantL1Store` vía REST, mismo seam)
- **Extractor de Hechos:** LLM call con prompt de extracción a tripletas SPO (`src/l1/extractor.ts`, con fallback heurístico local)
- **UI Nuevo:** Panel "Memory > L1 Atomic Facts Index" en el launcher (`src/L1Panel.tsx`)
