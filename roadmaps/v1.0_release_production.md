# Neura-Core v1.0 — Release: Production Hardening & Analytics Dashboard

> **Objetivo:** Versión de producción completa lista para clientes B2B. Incluye hardening de infraestructura (K8s, failover, backups), dashboard de analíticas de negocio (EQ scores, sesiones, ROI), documentación completa de la API, y el launcher en su versión final con todas las funcionalidades integradas.

---

## Stack Adicional Esta Versión

- **Orquestación:** Kubernetes (minikube local / GKE/EKS para producción)
- **Backup:** pg_dump programado + Redis RDB snapshots + Qdrant snapshots
- **Documentación API:** Swagger UI / Scalar + `utoipa` Rust crate
- **Analytics Engine:** ClickHouse (columnar) para eventos de sesión a escala
- **Launcher Final:** Versión pulida y compilada para distribución (`.exe`, `.dmg`, `.AppImage`)
- **UI Nuevo:** Panel "Analytics Dashboard" con métricas de negocio B2B

## Hito 10.2 — Failover: Graceful Degradation & Circuit Breaker

**Entregable usable:** Escenarios de fallo probables demuestran que el sistema no colapsa y entrega estado neutro.

### Sub-metas
- [ ] Circuit Breaker Rust con `failsafe` o implementación propia: `CLOSED → OPEN → HALF_OPEN`
- [ ] Si VAD Engine falla → fallback a estado neutro VAD (0.0, 0.0, 0.0) con log de warning
- [ ] Si LLM supera latencia > 500ms → respuesta de fallback pre-generada para el vertical
- [ ] Si Qdrant falla → continuar con solo L2+L3 (degradación parcial, no caída total)
- [ ] Panel "Admin > Circuit Breakers": estado de cada breaker (CLOSED/OPEN/HALF_OPEN) en tiempo real
- [ ] Botón "Simular fallo de [subsistema]" para pruebas manuales

### ✅ Revisión Manual Requerida
- Simular fallo del VAD Engine y verificar que la respuesta del agente sale con VAD neutro sin error al cliente
- Simular latencia LLM > 500ms y verificar que el cliente recibe la respuesta de fallback en ≤ 600ms total
- Restaurar el servicio fallado y verificar que el Circuit Breaker pasa de OPEN a HALF_OPEN a CLOSED automáticamente
